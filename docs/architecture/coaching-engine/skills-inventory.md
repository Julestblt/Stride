# Skills inventory: ai-running-coach to Stride

- Status: Accepted (issue [#129](https://github.com/Julestblt/Stride/issues/129)), applying decision D10 of the [coaching team proposal](coaching-team-proposal.md)
- Reference: [mmornati/ai-running-coach](https://github.com/mmornati/ai-running-coach) at tag v1.3.0, commit `510b2d52966d817b87e42af6273b16854e77e148`, MIT. The earlier [reference audit](reference-audit.md) read v1.2.0; this document does not repeat it.
- Ported skills: `managed-agents/skills/status-reports`, `explain-decision` and `garmin-data-access`, with the MIT notice in `managed-agents/skills/NOTICE`.

## Summary

- The reference ships 22 skills. Stride adapts 5 of them into 3 skills, defers 6 and drops 11.
- Most reference skills are integration plumbing for a single-athlete Markdown workspace: file contracts, sync, installers, Garmin and Intervals.icu writes. Stride owns that work in code, in the database or in garmin_mcp.
- Most coaching substance lives in the reference's agent files, not in its skills. The [agent knowledge map](#agent-knowledge-map) shows where each part lands in Stride.
- The ported skills read plan progress and decisions through `read_plan_progress` and `read_plan_history`, built in #137.

## Ported skills

| Stride skill         | Derived from                                   | Attached to       | What changed                                                                                                                                                         |
| -------------------- | ---------------------------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `status-reports`     | `today`, `week`, `race`                        | Coach             | One skill for the three factual answers. File reads and scripts become Stride tools; weather, Trail Shape, load forecast, gear lines and guardrail runs are dropped. |
| `explain-decision`   | `why`                                          | Coach             | The decision log becomes the plan proposal record (title, summary, rationale, operations, specialist opinions, status). The personal synthesis is dropped.           |
| `garmin-data-access` | `garmin-sync-efficiency`, `today` morning rule | Coach and Medical | Persistence, sync markers, gear, weight and other sources are dropped. Stride context comes first and each agent stays within its garmin MCP allowlist.              |

None of the ported skills calls a Garmin write tool, sets a weight target or gives treatment advice.

## Plan progress and history tools

Built in #137 in the typed tool registry (`src/server/coaching/tools`); the ported skills use them without fallbacks.

| Tool                 | Returns                                                                                                                                                                                                             | Source in Stride                                                                               | Used by            |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------ |
| `read_plan_progress` | Planned sessions for a date range of at most 42 days with their status (completed, partial, substituted, missed, dismissed, upcoming, rest) and the matched activities' duration, distance and elevation            | Stored planned-versus-completed matches (`src/server/plans/matches.ts`), `provider_activities` | `status-reports`   |
| `read_plan_history`  | Plan proposals newest first with title, summary, rationale, operations, origin, scope, status, dates, validation result when recorded, specialist opinions and decisions; one proposal by id; no active plan needed | `plan_proposals`, `plan_decisions`                                                             | `explain-decision` |
