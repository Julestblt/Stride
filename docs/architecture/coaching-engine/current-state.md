### What the design references imply

The approved references define the coaching experience the engine must serve:

- **Plan** (`app/plan`): blocks (for example Reconstruction, Volume, Ultra-spécifique, Affûtage) containing weeks with planned hours; a week view with structured sessions, compliance per completed session, and a "Changements de la semaine" list with pending and accepted changes and their reasons.
- **Historique** (`app/plan-ledger`): "Chaque changement de ton plan, et pourquoi. Rien ne bouge en silence." Each entry shows before/after session shapes, signal chips (sleep, HRV, load), who proposed it (Récupération, Entraînement, Performance, Agenda, Course or the athlete in Coach), a decision deadline ("à décider avant 17:00"), the athlete's note on refusal, an undo action for accepted changes, an outcome follow-up, block-level changes, the plan creation entry, and an **"Automatique · mineur"** change with an undo window.
- **Approve change** (`app/approve-change`): one proposal with before/proposed shapes, the reason signals with their usual ranges, a confidence level, and Accepter / Garder actions.
- **Coach** (`app/coach`): "Les conversations se réinitialisent chaque matin. Les décisions et ce que j'apprends sont conservées." A morning brief, inline proposals inside the conversation, a visible tool-progress line ("Je vérifie l'espacement…"), pending decisions with expiry, ongoing follow-up threads per domain, a "Ce que je sais de toi" list of facts with provenance (told, observed, followed up), and targeted questions to refine the plan.
- **Today** (`app/today`): the day's verdict, the proposed change, body signals, yesterday's compliance, a short check-in question.
- **Workout detail** (`app/workout-detail`): structured steps with targets, the reason for the session, the athlete's habits, "si ça se passe mal" contingencies, cues, fueling, shoes, best time slot, and an **"Envoyer sur Garmin"** action.

Two elements need product decisions because they go beyond "every change is approved": automatic minor changes and sending workouts to Garmin ([risks and decisions](risks-and-decisions.md)).

## garmin_mcp

| Area                                                    | State    | Evidence and notes                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity and tenancy                                    | Verified | Every REST and MCP request is verified by calling Supabase `GET /auth/v1/user` with the bearer token (10 s timeout, no cache); the returned id is the tenant. Client-supplied ids are ignored.                                                                                                                                                                                      |
| Connection lifecycle and MFA                            | Verified | Start, MFA continuation, disconnect, delete data; encrypted Garmin sessions (Fernet); five attempts per ten minutes per user.                                                                                                                                                                                                                                                       |
| Historical and incremental sync                         | Verified | Durable `sync_jobs` with leases, attempts and backoff; activities in 7-day windows newest first; recovery from 90 days back, fitness from 365 days back; hourly incremental jobs revisiting 14 days of activities and 7 days of daily metrics; lease-gated compare-and-set writes.                                                                                                  |
| Normalized activities                                   | Verified | `provider_activities` (type, start, local start, time zone, distance, duration, elevation gain/loss, heart rate, cadence, power, training effect, name, calories, Garmin RPE 1–10, feel), `provider_activity_segments` (laps, splits), `provider_activity_tracks` (route ≤ 300 points, aligned series ≤ 240 points, full-resolution heart-rate histogram; last 90 days by default). |
| Daily observations                                      | Verified | `provider_observations` with availability (`available`, `missing`, `partial`, …): sleep phases and score, HRV last night and weekly, HRV status, resting HR, stress, Body Battery, steps, respiration, SpO₂, training readiness, recovery time, VO₂ max, training status, acute and chronic load, load focus.                                                                       |
| Intraday wellness                                       | Verified | `GET /v1/wellness/days/{date}` fetched live from Garmin, never stored, cached 5 minutes (today) or 6 hours (past).                                                                                                                                                                                                                                                                  |
| Weekly patterns                                         | Verified | `provider_training_weeks` view (security invoker).                                                                                                                                                                                                                                                                                                                                  |
| MCP in Stride mode                                      | Verified | Streamable HTTP, stateless, Supabase bearer required, host allowlist. Ten read-only tools by default: `get_activities`, `get_activity`, `get_activity_splits`, `get_stats`, `get_sleep_data`, `get_hrv_data`, `get_training_readiness`, `get_training_status`, `get_rhr_day`, `get_vo2max_trend`. Startup refuses any tool not prefixed `get_`, `count_`, `search_` or `download_`. |
| What MCP tools read                                     | Verified | **Live Garmin Connect**, through a per-user Garmin client that takes the same session lease as the sync worker. MCP tools do not read the normalized tables, and return Garmin-shaped payloads. The service's own documentation says other consumers should use normalized rows rather than live Garmin calls.                                                                      |

### Deployed endpoint (unauthenticated probes, 2026-10-12)

| Request                                         | Result                                                                             |
| ----------------------------------------------- | ---------------------------------------------------------------------------------- |
| `GET /healthz`                                  | 200 `ok`                                                                           |
| `GET /readyz`                                   | 200 `{"status":"ready"}`                                                           |
| `GET /v1/connections/garmin/sync` without token | 401 `unauthorized`                                                                 |
| `POST /mcp` initialize without token            | 401 `invalid_token`, `WWW-Authenticate: Bearer`                                    |
| `GET /.well-known/oauth-protected-resource`     | 404: no OAuth discovery metadata; clients must send the Supabase bearer explicitly |

The service remains publicly reachable, which the Garmin architecture document already flags as a change requiring approval (draft G5).
