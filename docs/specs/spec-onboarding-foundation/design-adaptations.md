# Onboarding design adaptations

The `Onboarding` artboards of the [design board](../../design/design-board.md) remain the visual source of truth. These adaptations apply only where the real API or an accepted product decision cannot support the mockup. Keep layout, hierarchy, tone and component language unchanged.

Profile feedback (#38): weekly bars, typical week and regularity use running sessions over sixteen Monday-based weeks; the header counts all sports. Five heart-rate zones are explicitly labelled Stride estimates, using Karvonen with a median resting baseline from at least seven valid observations over 28 calendar days, or percentages of observed maximum when resting data is insufficient. Source, method and inputs are shown; unavailable maximum produces no zones. The habits section reuses volume/mix insights with all-sport twelve-month provenance, optional AI attribution and deterministic endpoint-failure fallback. Other predictions remain deferred.

Mobile profile actions stay in the page flow beneath all profile sections so completion and correction controls cannot cover fitness values. Other onboarding screens retain their sticky mobile actions.

Profile sections use three columns on desktop (1280px and wider), two columns on compact desktop, and one column on mobile. Reading order remains training, fitness, recovery, zones, goals, habits. Five zone ranges share a colored horizontal strip; habits use section dividers, while the import screen retains its framed insights card. The desktop profile moves the back action into the step header and uses the reference content inset.
